# System Design Glossary

A living glossary. Add a concise definition and link to a lesson when a term is introduced.

| Term | Working definition |
|---|---|
| Availability | Fraction of time a service meets its defined usable condition. |
| Backpressure | A signal or mechanism that slows producers when downstream consumers cannot keep up. |
| Cache | A faster, usually derived store, retaining data to reduce repeated work or latency. |
| CAP theorem | During a network partition, a distributed data system must choose between providing a linearizable consistency guarantee and responding to every request; it does not say systems simply choose any two at all times. |
| CDN | Distributed edge infrastructure that can serve content closer to clients and reduce origin work. |
| Consistency | Rules describing what values operations may observe in a concurrent or replicated system. |
| Durability | Guarantee that committed data survives specified failures. |
| Idempotency | Repeating an operation has the same intended effect as performing it once. |
| Latency | Time taken for an operation or request. |
| Load shedding | Deliberately rejecting or dropping lower-priority work to protect system health. |
| p95 / p99 | 95th / 99th percentile of a measured distribution. |
| QPS / RPS | Queries or requests per second. |
| Replication | Keeping copies of data or service state on multiple nodes. |
| SLI | A measured indicator of service behavior. |
| SLO | A target or objective for an SLI over a defined window. |
| Sharding | Splitting a dataset across partitions or nodes, often by key. |
| Throughput | Amount of work completed per unit time. |
