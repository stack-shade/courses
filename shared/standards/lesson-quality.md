# Lesson Quality Standard

A lesson is ready to publish when it helps a learner understand and apply a concept, not merely recognize terminology.

## Minimum quality checklist

- [ ] State the target level, prerequisites, status and measurable objectives.
- [ ] Introduce the problem and context before tools or patterns.
- [ ] Explain terminology in plain language and then precise technical terms.
- [ ] Include a diagram, worked example, comparison or experiment where it improves understanding.
- [ ] Label assumptions, estimates, constraints and units.
- [ ] Discuss trade-offs, limitations, failure modes and security implications where relevant.
- [ ] Include retrieval questions and a practical task.
- [ ] Link primary sources and distinguish evidence from opinion.
- [ ] Add a next step and make sure relative links resolve.
- [ ] Review readability on mobile and ensure diagrams have explanations / alt text.

## Visual principles

- One diagram should answer one question.
- Label arrows with what moves: request, response, event, bytes or ownership.
- Use consistent shapes for clients, services, stores, queues and trust boundaries within one course.
- Avoid tiny text, vendor logos as architecture, unnecessary 3D effects and decorative complexity.
- Keep the editable source (Mermaid, PlantUML, Structurizr, SVG, etc.) alongside exported images.
- Do not rely on color alone to communicate meaning.

## Status meanings

- **planned:** listed in the course plan; no substantial learning content yet.
- **draft:** first content exists but needs verification or editing.
- **review:** content is complete enough for peer / technical review.
- **published:** lesson has been checked against its sources and quality checklist.
- **archived:** content is retained for history but should not be treated as current guidance.

## Technical accuracy

For changing APIs and product behavior, cite versioned official docs and mention the checked date. For distributed-systems claims, state the failure model and consistency semantics. Never label a rough estimate as a measured result.
